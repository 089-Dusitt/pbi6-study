ภาพรวมงานทีม

ตามเส้นทางของนักศึกษาตั้งแต่ดูตารางรวมจนถึงเลือก เปลี่ยน และลบ section

  1. PBI1 ดูตารางรวม
    หน้าแรกใช้ loadSchedules() โหลดข้อมูลจาก GET /api/v1/schedules แล้ว renderTable() สร้างแถวในตาราง ดู loadSchedules()
  2. PBI2 กรองตามชั้นปี
    ปุ่มชั้นปีเปลี่ยน yearLevel ใน URL ถ้ามีตารางรวมใน cache จะกรองจากข้อมูลนั้น ถ้ายังไม่มีจึงขอข้อมูลของปีที่เลือกจาก API ดู fetchRows() และ getRows()
  3. PBI3 ล็อกอิน
    ลิงก์ My Schedule เปิดหน้าที่เรียก requireSignIn() ผ่าน Keycloak สำหรับ role student โค้ดส่ง user.username เป็นรหัสนักศึกษาให้ showStudent() ดูจุดเรียก Sign In
  4. PBI4 โหลด My Schedule
    showStudent() เอาชั้นปีและกลุ่มไปโหลดตาราง แล้วอ่านรายการที่เลือกไว้จาก GET …/selections ฟังก์ชัน rememberSelections() เก็บเป็น selectedSection ก่อนวาดสองตาราง ดู showStudent()
  5. PBI5 เลือก section
    selectSection() ส่ง POST …/selections พร้อม { courseId, section } เมื่อได้ 201 จึงเก็บค่าใน selectedSection[courseId] แล้วเรียก render() ดู selectSection()
  6. PBI6 ลบรายการ
    ปุ่ม Remove ส่ง DELETE …/selections/:courseId เมื่อได้ 204 จึงลบคีย์ที่ PBI5 เพิ่มและเรียก render() ของ PBI4 ดู removeSelection()
  7. PBI7 เปลี่ยน section
    changeSection() ส่ง PUT …/selections/:courseId พร้อม section ใหม่ เมื่อได้ 200 จึงเขียนค่าทับคีย์เดิม แล้วเรียก render() เหมือน Select และ Remove ดู changeSection()
ลองเล่าภาพรวมในหนึ่งนาที แล้วเปิดดูตัวอย่างคำตอบ

งานทีมเริ่มจากหน้าแสดงตารางเรียนรวมที่เลือกดูตามชั้นปีได้ พอเข้า My Schedule ระบบล็อกอินผ่าน Keycloak แล้วใช้รหัสนักศึกษาไปโหลดตารางและวิชาที่เลือกไว้ เพื่อนทำ Select ซึ่งเพิ่ม section ใน selectedSection ส่วนผมทำ Remove ซึ่งส่ง DELETE แล้วลบคีย์จาก object เดียวกัน Change ก็ใช้ object นี้เหมือนกัน โดยเขียน section ใหม่ทับค่าเดิม ทั้งสามฟีเจอร์เรียก render() เพื่ออัปเดต My Schedule และ Courses to Choose พร้อมกันครับ

ซ้อมสอบ Frontend Assessment

ฝึกอธิบายการออกแบบ ชี้บรรทัดที่งานของทีมเรียกโค้ดของคุณ แล้วสาธิตให้เห็นผล

ใครรับผิดชอบอะไร

  • Dusit (คุณ)ทำ PBI6 Remove ทั้งปุ่ม กล่องยืนยัน การส่ง DELETE และการจัดการผล รวมถึงมีส่วนทำ Sign In/Out ใน PBI3
  • Kongpopทำ My Schedule (PBI4) และ API สำหรับ Select (PBI5) โค้ด Remove ใช้ fillTable() กับ render() ของเขา
  • Phurinทำ Change Section (PBI7) และมีส่วนใน Class Schedule, ตัวกรองชั้นปี และ PBI3 การ Change จะวาดแถวใหม่ ทำให้ Remove แสดง section ปัจจุบัน
ตัวอย่างคำตอบว่า PBI6 ของคุณทำงานยังไง

ผมทำ PBI6 Remove ครับ ตอนวาดตาราง fillTable() ของเพื่อนเรียก createRemoveButton() ของผมเพื่อสร้างปุ่มให้แถวที่เลือกเอง พอกดยืนยัน ปุ่มเรียก removeSelection(courseId) ให้ส่ง DELETE ถ้าได้ 204 ผมจะลบคีย์จาก selectedSection แล้วเรียก render() ของเพื่อน เพื่อให้ section ของวิชานั้นกลับไปอยู่ใน Courses to Choose ครับ

คำถามต่อว่าเขียนแบบนี้ทำไม

ทำไมส่ง onConfirm: removeSelection โดยไม่มีวงเล็บ?

ตอนสร้างปุ่ม เราส่งฟังก์ชันไปเก็บไว้ก่อน พอยืนยันจึงเรียก onConfirm(course.id) ให้ลบวิชาของแถวนั้น ดูโค้ดสร้างปุ่ม

ทำไมต้องล้าง returnValue และตั้ง once: true?

ล้างค่าเพื่อกัน "remove" จากรอบก่อนค้างตอนกด Esc ส่วน once: true เอาตัวฟังออกหลังกล่องปิดหนึ่งครั้ง เพื่อกันตัวฟังหลายรอบสะสม

ทำไม 204 วาดใหม่ได้ทันที แต่ 404 ต้องอ่านข้อมูลใหม่?

204 ยืนยันว่าลบสำเร็จ หน้าเว็บลบคีย์ที่จำไว้แล้ววาดใหม่ได้ ส่วน 404 อาจเป็นข้อมูลค้างจากอีกแท็บ จึงอ่านรายการล่าสุดหลังปิดกล่อง ดูโค้ดจัดการผล

ทำไมลบ section 7 แล้ว section อื่นกลับมาด้วย?

ค่า { 45: 7 } เก็บ section 7 ไว้ใต้รหัสวิชา 45 เมื่อเอาคีย์ 45 ออก render() จะรู้ว่าวิชานี้ยังไม่ได้เลือก แล้วแสดงทุก section ที่เลือกได้อีกครั้ง ดูโค้ดวาดตาราง

เพิ่งกด Change ทำไม Remove ถึงรู้ section ใหม่?

Change เขียน section ใหม่ลง selectedSection แล้ววาดตารางใหม่ ปุ่ม Remove ของแถวใหม่จึงใช้ข้อมูล section ล่าสุด

ซ้อมชี้สามจุด my-schedule.js บรรทัด 97 ส่งฟังก์ชัน → remove-selection.js บรรทัด 25 เรียกเมื่อยืนยัน → my-schedule.js บรรทัด 198 ถึง 200 วาดใหม่หลังลบสำเร็จ

ฝึกชี้โค้ดจริง

เปิดไฟล์แล้วชี้ว่าปุ่ม Remove เริ่มมาจากไหน

ชี้ที่ fillTable() ใน my-schedule.js ฟังก์ชันนี้ส่งแถวและ onConfirm: removeSelection เข้า createRemoveButton() ที่คุณเพิ่ม แล้วเอาปุ่มที่ได้ไปใส่ในช่องเดียวกับปุ่ม Change ของแถวนั้น เปิดบรรทัดที่สร้างปุ่ม

ชี้บรรทัดที่มีผลเมื่อกด Remove กับ Cancel ต่างกัน

เปิด remove-selection.js แล้วชี้ว่า handler ใน event close เรียก onConfirm(course.id) เมื่อ returnValue เป็น "remove" เท่านั้น ส่วน Cancel กับ Esc ไม่ผ่านเงื่อนไขนี้ เปิดบรรทัดที่ตรวจผลจากกล่อง

ชี้ว่าผลจาก API กลับมาเปลี่ยนสองตารางตรงไหน

ใน removeSelection() เมื่อได้ 204 ให้ชี้ delete selectedSection[courseId] และ render() แล้วเปิดตัวกรองใน render() เพื่ออธิบายว่าทำไมทุก section ของวิชานั้นกลับมาให้เลือก ถ้าได้ 404 ให้ชี้ rereadSelections() ที่ทำงานเมื่อกล่องข้อความปิดด้วย OK หรือ Esc เปิดบรรทัดที่จัดการผล DELETE

หลัง Change แล้วกล่อง Remove รู้ section ใหม่ได้ยังไง?

เมื่อ PUT ได้ 200 โค้ดแก้ selectedSection[courseId] แล้ว render() ส่ง schedule ของ section ใหม่ให้ fillTable() เพื่อสร้างปุ่ม Remove อีกครั้ง เปิดโค้ด Change

ลองตอบออกเสียงก่อนกดเปิดคำตอบ

ทำไม Fixed ไม่มีปุ่ม Remove?

เพราะเป็นคาบที่ระบบกำหนดไว้ให้ createRemoveButton() คืน null เมื่อ schedule.fixed เป็นจริง

กด Cancel หรือ Esc แล้ว API ถูกเรียกไหม?

ไม่ถูกเรียก เพราะ handler ตรวจว่า returnValue === "remove" ก่อน ส่วนค่าจากครั้งก่อนถูกล้างทุกครั้งที่เปิดกล่อง

ลบ section 7 แล้วทำไม section อื่นของ LNG202 กลับมาด้วย?

ตารางตัวเลือกซ่อนทั้งวิชาเมื่อมี courseId อยู่ใน selectedSection พอลบคีย์ของ LNG202 ออก render() จะส่งทุก section ที่ไม่ fixed ไปยัง Courses to Choose

204 ต่างจาก 404 ยังไงในหน้าเว็บ?

204 คือ backend ลบสำเร็จ หน้าเว็บลบคีย์จาก selectedSection ทันที ส่วน 404 สื่อว่าหา selection ที่จะลบไม่เจอ เมื่อปิดกล่องข้อความด้วย OK หรือ Esc หน้าเว็บจะดึงรายการปัจจุบันจาก server ใหม่

ส่วนของเราต่อกับ PBI4 และ PBI5 ตรงไหน?

PBI4 โหลดตารางและ selections เดิม PBI5 เพิ่ม selection ด้วย POST ส่วน PBI6 ลบ selection เดียวกันด้วย DELETE ทั้งสามส่วนใช้ข้อมูลชุดเดียวและวาด My Schedule กับ Courses to Choose จาก render()

ลบจากหน้าเว็บอย่างเดียว หรือจากฐานข้อมูลด้วย?

ในโปรเจกต์จริง backend ลบจากตาราง selections ก่อนตอบ 204 แล้ว frontend จึงลบคีย์จาก selectedSection และวาดใหม่ เว็บติวนี้แค่จำลองทั้งสองฝั่งไว้ในหน่วยความจำ
